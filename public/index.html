See what your AI agents can see.

keypeek checks your machine for API keys that tools like Claude Code, Cursor and Codex can reach: in their own transcripts, your shell history and your .env files. It takes a few seconds, changes nothing and never shows a secret.

npx @evalogical/keypeek

Free and open source (MIT). Needs Node 20 or newer. macOS and Linux.

Where agents find your keys

Secret scanners look at git history. Your agents look somewhere else. keypeek checks the four places they actually read.

Agent transcripts high
If a key was ever pasted into a chat, a model has already seen it. Rotate it. ~/.claude~/.codex~/.gemini~/.cursor
Shell history high
Any agent that can run commands can read this file, and every key you ever typed into a command is in it. ~/.zsh_history~/.bash_historyfish history
.env files medium
Agents read these by default. Template files like .env.example are skipped. .env, .env.local, .env.production … under your home folder
Environment variables low
Every command an agent runs inherits the environment of your shell. the shell that runs keypeek
Agent settings
keypeek also tells you whether Claude Code has a deny rule for .env. It reports what is set. It does not change anything.

Four steps, a few seconds

  1. Find

    It looks in the places agents look: transcripts, shell history, .env files and your shell's environment.

  2. Match

    Known key formats from Anthropic, OpenAI, GitHub, AWS, Stripe, Google, Slack, Hugging Face and others, plus a conservative rule for names like API_KEY or PASSWORD that hold high-entropy values.

  3. Rank

    A key already in a transcript counts for more than a key in an unused .env. Points are capped per surface so one noisy folder cannot hide progress elsewhere.

  4. Redact

    Only a 4-character prefix, the length and a hash fingerprint leave the scanner. The full value is never stored in a result.

The score starts at 100 and goes down with each finding.

Check the promises yourself

  • Read-only

    It never writes, moves or deletes anything. A test compares file modification times before and after a scan.

  • Offline

    No network, no telemetry. The package has zero runtime dependencies.

  • Never shows a secret

    Results hold a prefix, a length and a fingerprint. A test scans both the text and JSON output for the full value.

The tool is about 430 lines of TypeScript, so you can read all of it. Or run this in a clone of the repository. It prints nothing:

grep -rE "node:(http|https|http2|net|tls|dns|dgram|child_process)|fetch\(|writeFile|appendFile|createWriteStream" src

If keypeek ever breaks one of these promises, please report it privately. See the security policy.

If it finds something

  1. Rotate it

    Anything in a transcript or shell history has already been in a model's context or sitting in plain text. Treat it as exposed.

  2. Move it out

    Keep secrets in a secrets manager or your OS keychain and inject them when you run a command, for example with op run from 1Password, Doppler or Infisical.

  3. Add a deny rule

    Tell your agent's file tools to skip .env. In Claude Code's settings.json:

    { "permissions": { "deny": ["Read(./.env)", "Read(./.env.*)"] } }

    A deny rule is not a full barrier: shell commands can still read the file. Check your agent's current docs for exact syntax.

  4. Run keypeek again

    Confirm the score went up.

Where keypeek fits

Who it's for

  • Solo builders who let an AI agent run in their projects.
  • Developers with a messy home folder: old .env files, keys in shell history, keys pasted into chats.
  • Small teams and agencies handing a laptop or repo to an AI agent.

What it is not

  • Not a replacement for gitleaks, trufflehog or GitGuardian. Those find secrets in repositories.
  • Not a secrets manager. 1Password, Doppler and Infisical keep secrets out of reach. keypeek tells you if you have the problem today.
  • They work well together: audit, fix, audit again.

Help build it

keypeek is open source and small enough to read in an afternoon. Good ways to start:

  • Pick a good first issue, such as adding a key format it does not detect yet.
  • Report a false positive or a missed key. Use a fake example, never a real secret.
  • Vote on the roadmap with a thumbs-up on the ideas you want.
  • Start a discussion with a question or an idea.

Questions

Does keypeek send my data anywhere?

No. The package has no network code and no telemetry, and this page has no analytics either.

Can it change or delete my files?

No. It only reads. A test checks that file modification times are unchanged after a scan.

Will it show me my secrets?

No. It prints a 4-character prefix and the length, never the full value.

It found a key in a transcript. What now?

Rotate the key. A transcript means a model has already seen it. Clearing the transcript afterwards is optional.

Is it a replacement for gitleaks or a secrets manager?

No. Those prevent and catch leaks. keypeek checks what your AI agents can reach on this machine.

Does it work on Windows?

Not tested yet. macOS and Linux are supported.

Can it miss secrets?

Yes. Detection is pattern-based, so new key formats can slip through and a few high-entropy values may be flagged by mistake. Cursor's chat database is not scanned yet. The known limits are listed in the README.
