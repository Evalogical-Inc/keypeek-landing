Secret scanners check your git history. Your AI agents read somewhere else.

An agent that can open files and run commands can read your old chats, your shell history and every .env under your home folder. keypeek is a small, read-only command-line tool that shows you what is sitting there, ranked by how exposed it is.

  • Read-only by design
  • No network, no telemetry
  • Never prints a secret
  • Zero runtime dependencies
  • A score from 0 to 100
  • JSON output for scripts

How it works

Four steps, a few seconds.

  1. Find

    It looks where agents look: transcripts, shell history, .env files and your shell's environment.

  2. Match

    Known key formats from Anthropic, OpenAI, GitHub, AWS, Stripe, Google, Slack, Hugging Face and others, plus a careful rule for names like API_KEY that hold high-entropy values.

  3. Rank

    Points are capped per place, so one noisy folder cannot hide progress elsewhere.

  4. Redact

    Only a 4-character prefix, the length and a hash fingerprint leave the scanner.

The score starts at 100 and goes down with each finding.

  • A90 and up
  • B75 and up
  • C55 and up
  • D35 and up
  • Fbelow 35
  • highTranscripts and shell history
  • medium.env files
  • lowEnvironment variables

If it finds something

Rotate, move it out, run it again.

  1. Rotate it

    Anything in a transcript or shell history has already been in a model's context or in plain text. Treat it as exposed.

  2. Move it out

    Keep secrets in a secrets manager or your OS keychain and inject them when you run a command, for example with op run from 1Password, Doppler or Infisical.

  3. Run keypeek again

    Confirm the score went up.

Add a deny rule. Tell your agent's file tools to skip .env. In Claude Code's settings.json:

{ "permissions": { "deny": ["Read(./.env)", "Read(./.env.*)"] } }

A deny rule is not a full barrier: shell commands can still read the file. Check your agent's current docs for exact syntax.

Don't take our word for it.

The tool is about 430 lines of TypeScript, so you can read all of it.

  • Read-only

    It never writes, moves or deletes anything. A test compares file modification times before and after a scan.

  • Offline

    No network, no telemetry. The package has zero runtime dependencies.

  • Never shows a secret

    Results hold a prefix, a length and a fingerprint. A test scans the text and JSON output for the full value.

Or run this in a clone of the repository. It prints nothing:

grep -rE "node:(http|https|http2|net|tls|dns|dgram|child_process)|fetch\(|writeFile|appendFile|createWriteStream" src

Found a broken promise? Report it privately. See the security policy.

Where keypeek fits

Who it's for

  • Solo builders who let an AI agent run in their projects.
  • Developers with a messy home folder: old .env files, keys in shell history, keys pasted into chats.
  • Small teams and agencies handing a laptop or repo to an AI agent.

What it is not

  • Not a replacement for gitleaks, trufflehog or GitGuardian. Those find secrets in repositories.
  • Not a secrets manager. 1Password, Doppler and Infisical keep secrets out of reach. keypeek tells you if you have the problem today.
  • They work well together: audit, fix, audit again.

Still curious about keypeek? Here are the answers.

Does keypeek send my data anywhere?

No. The package has no network code and no telemetry, and this page has no analytics either.

Can it change or delete my files?

No. It only reads. A test checks that file modification times are unchanged after a scan.

Will it show me my secrets?

No. It prints a 4-character prefix and the length, never the full value.

It found a key in a transcript. What now?

Rotate the key. A transcript means a model has already seen it. Clearing the transcript afterwards is optional.

Is it a replacement for gitleaks or a secrets manager?

No. Those prevent and catch leaks. keypeek checks what your AI agents can reach on this machine.

Does it work on Windows?

Not tested yet. macOS and Linux are supported.

Can it miss secrets?

Yes. Detection is pattern-based, so new key formats can slip through and a few high-entropy values may be flagged by mistake. Cursor's chat database is not scanned yet. The known limits are listed in the README.

How do I update it?

npx @evalogical/keypeek@latest always runs the newest version. If you installed it globally, run npm install -g @evalogical/keypeek@latest.
